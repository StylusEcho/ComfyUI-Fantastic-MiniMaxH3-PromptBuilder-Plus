# Development Workflow

The project work queue is in `TASKS.md`.

When asked to work through the task list:

1. Read this file and `TASKS.md` before making changes.
2. Work on tasks in sequential priority/order unless a dependency requires otherwise.
3. Before starting a task, inspect the relevant existing implementation.
4. Do not implement unrelated changes.
5. Run the relevant tests/checks after each task.
6. Only mark a task complete once its acceptance criteria are satisfied.
7. Update `TASKS.md` as work progresses:
`🟦` pending
`🟨` in progress
`🟩` complete
`🟥` blocked
`❓` explain
8. Add a short completion note beneath completed tasks describing what changed.
9. If a task is ambiguous or needs more explicit instruction, mark it with `❓`
10. If genuinely blocked, mark it `🟥`, explain why, and continue to the next independent task if it doesn't conflict/isn't dependent on a previous item
